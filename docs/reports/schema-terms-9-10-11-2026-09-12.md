## Term 11 — and this is the biggest number left in phase 1

A cup gated on a kind the classifier could not place closes in silence, exactly as a cup gated on an
unanswered optional fact does. Measured from the 17 committed ledgers:

```
45,356  Cisco parts classed hardware
 8,788  (19.4%) sit in a FALLBACK kind — unknown / other / component / accessory / (none)
        and are therefore asked 0 or 1 cups, where a NAMED kind in the same category
        is asked between 1 and 39
```

Then the question that decides whether that is a shaping gap or a classification one: **what does
today's rule table say those 8,788 are?** `parts.product_class` only moves when a reclassify run
executes, and none has run since the last two days of class rules landed.

```
1,550  (17.6%)  today's rules ALREADY call non-hardware — they are in the 19.4% only
                because item 10 has not run. UC 1,458 of its 1,519, conferencing 75 of 77.
7,238  (82.4%)  STAY hardware in a fallback kind. 16.0% of Cisco hardware, asked ~nothing.
                THIS IS THE REAL RESIDUE.
```

**AND THE FIRST MEASUREMENT OF IT WAS WRONG, which is worth more than the number.** The first run
reported *100.0% would leave hardware, 0 stay* — and an exactly-100 beside an exactly-0 is the shape
of a broken comparison, not a finding. `classify()` takes `categorySlug` and `categoryIsHardware`;
the call passed `category`, which is not a field, so `categoryIsHardware` was `undefined` — "the
category is not known" — and every row no SKU rule decided fell through the unknown-category branch
and read as non-hardware. Third replay-fidelity error of the day, after the census's two. The
corrected call reads `is_hardware` from the `categories` table rather than assuming it.

### What the 7,238 are — a first cut, and its edges are wrong

| n | shape | own facts | linked to a doc |
| --- | --- | --- | --- |
| 4,576 | **unclassified — needs reading** | 407 | 3,611 |
| 1,512 | mechanical / accessory: kit, blank, bracket, rail, panel, cable | 247 | 1,335 |
| 1,061 | "a datasheet cell enumerated as a part" | **507** | **676** |
| 89 | storage media: SSD, SD card, drive | 6 | 71 |

The cell bucket is the broken one and its own numbers say so: 507 of 1,061 carry an **own** fact and
676 are linked to a document. The six-to-eight-digit Scientific-Atlanta PIDs (`4028905`, `737400`,
`1030181`) are **real products** — this repo's `CLAUDE.md` says exactly that, and a predicate built
on "surely a number is not a part" is the mistake it was written down to prevent. So this table is
not a proposal; it is the reason a survey was commissioned instead of a rule.

`CWDM-MUX-4-SF2=` is the shape worth naming: a real CWDM multiplexer, in `transceiver`, in the
fallback kind, asked nothing.

### Why this is not fixed in this pass

The fix is a kind with a cup set per family, which means editing `src/core/fieldSchema.ts` and the
kind classifiers — and six agents are editing exactly those files this hour (round-3 items 5–9 and
the wireless/UC class residue). A read-only survey is running against the 7,238 instead: families
read in full, a verdict per family (needs a kind / is not a product / an existing kind should claim
it), ranked by parts touched, with the own-fact and document counts that separate "a product nobody
described" from "a row that is not a product".

**So phase 1 has one named, measured, unfinished item, and this is it.** It is not a surprise waiting
in the reviewer's next round; it is 16.0% of Cisco hardware with a survey pointed at it.
